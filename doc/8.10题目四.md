# 8.10 题目四：CAN 2.0 标准数据帧与简易协议对比

## 1. CAN 标准帧字段结构

CAN 2.0A 标准数据帧（Standard Data Frame）共 11 位 ID，各字段如下：

| 字段 | 位数 | 说明 |
|------|------|------|
| SOF（Start of Frame） | 1 bit | 帧起始，固定为显性电平（0） |
| Arbitration Field（ID） | 11 bit | 标准帧标识符，决定总线仲裁优先级（越小优先级越高） |
| RTR（Remote Transmission Request） | 1 bit | 数据帧为 0（显性），远程帧为 1（隐性） |
| IDE（Identifier Extension） | 1 bit | 标准帧为 0，扩展帧为 1 |
| r0（Reserved） | 1 bit | 保留位 |
| DLC（Data Length Code） | 4 bit | 数据段字节数（0~8） |
| Data Field | 0~64 bit（0~8 字节） | 实际载荷数据 |
| CRC Field | 15 bit CRC + 1 bit 定界符 | 循环冗余校验，生成多项式 x¹⁵+x¹⁴+x¹⁰+x⁸+x⁷+x⁴+x³+1 |
| ACK Field | 1 bit ACK + 1 bit 定界符 | 发送方发隐性，接收方正确收到后写显性确认 |
| EOF（End of Frame） | 7 bit | 帧结束标志，连续 7 个隐性位 |
| IFS（Interframe Space） | 3 bit | 帧间间隔，连续 3 个隐性位 |

**不含 IFS 的完整帧长：** 1+11+1+1+1+4+0~64+16+2+7 = **44 ~ 108 位**

## 2. CAN CRC 与本作业校验和的对比

| 对比维度 | CAN CRC | 本作业简易校验和 |
|----------|---------|------------------|
| 算法 | 多项式除法（CRC-15），生成多项式有 4 个非零项 | 字节相加取低 8 位 |
| 长度 | 15 bit | 8 bit |
| 检错能力 | 可检测：所有单/双位错误、奇数位错误、≤5 位突发错误、任意长度奇数个错误。漏检概率极低 | 可检测：单字节传输错误。但两个字节同时出错且和不变时漏检（如 0x0A+0x5A = 0x64，若 0x0B+0x59 = 0x64 同样通过） |
| 计算复杂度 | 需要硬件或软件逐位异或+移位，耗时 | 三次加法一次截断，极快 |
| 适用场景 | 车载、工业等高干扰环境，数据完整性要求高 | 教学演示、低干扰短距通信 |

**相同点：** 都位于数据之后、帧尾之前；都是由发送方计算填入、接收方重新计算比对；检测到不匹配都丢弃帧。

**核心差异：** CAN CRC 是工业级差错检测，能覆盖绝大多数传输错误模式；本作业的加法校验和教学成本低、代码量少，但在检错能力上与 CRC 差距巨大。真实产品中不可用加法校验和替代 CRC。

## 3. 机器人内部 CAN 总线电机控制帧设计

假设场景：四足 / 轮式机器人的关节电机通过 CAN 总线与控制板通信。

### ID 划分（11 bit）

| 位段 | 宽度 | 用途 |
|------|------|------|
| bit10~bit8（3 bit） | 消息类型 | 0: 紧急停机，1: 位置指令，2: 速度指令，3: 力矩指令，4: 状态查询，5: 参数配置，6~7: 保留 |
| bit7~bit5（3 bit） | 目标电机 ID | 0~7 对应 8 路电机（0 可保留为广播地址） |
| bit4~bit0（5 bit） | 发送源 / 优先级微调 | 区分主控板、IMU、电源管理模块等 |

优先级规则：紧急停机（000）优先级最高，状态查询（100）优先级最低。目标电机 ID 靠前让仲裁时先按功能分类再按电机编号决出胜负。

### 数据段划分（8 字节）

#### 位置指令帧（消息类型 = 1）

| 字节 | 内容 | 说明 |
|------|------|------|
| Byte 0 | 目标角度高 8 位 | 0.01° 分辨率，16 位覆盖 0~360° |
| Byte 1 | 目标角度低 8 位 | |
| Byte 2 | 目标角速度高 8 位 | 0.1°/s 分辨率 |
| Byte 3 | 目标角速度低 8 位 | |
| Byte 4 | 前馈力矩高 8 位 | 0.01 N·m 分辨率 |
| Byte 5 | 前馈力矩低 8 位 | |
| Byte 6 | 控制字 | bit0: 使能，bit1: 急停，bit2: 绝对/增量位置，bit3~7: 保留 |
| Byte 7 | 帧序号 / 心跳计数 | 每发一帧 +1，接收方据此检测丢帧 |

#### 状态查询帧（消息类型 = 4）

| 字节 | 内容 | 说明 |
|------|------|------|
| Byte 0 | 当前角度高 8 位 | |
| Byte 1 | 当前角度低 8 位 | |
| Byte 2 | 当前速度高 8 位 | |
| Byte 3 | 当前速度低 8 位 | |
| Byte 4 | 当前力矩高 8 位 | |
| Byte 5 | 当前力矩低 8 位 | |
| Byte 6 | 状态字 | bit0: 使能状态，bit1: 故障，bit2: 到达目标，bit3: 过温，bit4: 过流 |
| Byte 7 | 帧序号 | 与下行同步 |

### 设计考量

- CAN 数据段最多 8 字节，单个电机指令恰好填满；多电机通过不同帧 ID 区分；
- ID 中嵌入消息类型和目标 ID，接收方可硬件过滤不需要的帧，减轻软件负担；
- 帧序号用于检测丢帧和重复帧，链路层可靠性由 CRC 保证，应用层用序号补漏；
- 保留位留出扩展空间，后续增加新指令类型不破坏旧帧结构。
